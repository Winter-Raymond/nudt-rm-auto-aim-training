# 绿球识别作业（first-homework）

识别视频里的**绿球**，用箭头标注它的**运动方向**和**速度**：

- 箭头方向 = 球的运动方向
- 箭头越长 = 速度越快，越短越慢

## 运行方法

只依赖 `opencv` 和 `numpy`：

```bash
# 安装（如果没装）
pip install opencv-python numpy

# 运行（在本目录下，生成 output.mp4）
python main.py
```

视频 `first-homework.mp4` 已放在本目录，直接运行即可。想改输入/输出，改 `main.py` 顶部 `INPUT` / `OUTPUT` 两个变量。

## 思路（每步对应 main.py 里的函数）

| 步骤 | 函数 | 说明 |
|---|---|---|
| 1. 读视频 | `main` | 1280×720 / 30fps / 473 帧 |
| 2. 找绿色 | `find_ball` | HSV 颜色分割，只留绿色像素 |
| 3. 区分球和圆柱 | `find_ball` | 见下面「本题的关键」 |
| 4. 记录球心 | `detect_all` | 每帧记一个 `(x, y, r)` |
| 5. 补丢失帧 | `fill_missing` | 丢帧用前后帧线性插值补上 |
| 6. 算速度方向 | `compute_velocity` | 先平滑去抖，再求速度 |
| 7. 画箭头 | `draw_overlay` | 箭头方向=方向，长度=速度 |
| 8. 写视频 | `main` | 输出 `output.mp4` |

## 本题的关键：画面里有两个绿色物体

视频里有一个**绿球**（目标）和一个**绿色圆柱**（干扰物），颜色几乎一样。

- 如果"取最大的绿色轮廓"，抓到的一定是**圆柱**（它更大），作业就做错了。
- 正确做法是用**形状**区分：球接近实心圆，圆柱不是。

判断"像不像实心圆"用比例 `轮廓面积 / 最小外接圆面积`：

| 物体 | 该比例 | 结果 |
|---|---|---|
| 绿球 | 0.75 ~ 0.96 | 接近 1，是实心圆 |
| 绿色圆柱 | 0.18 ~ 0.73 | 明显小，不是圆 |

所以代码里取**实心圆占比最高**的轮廓，再用阈值 `FILL_MIN = 0.73` 兜底，就一定能挑出球。

## 速度与箭头

- 球心位置先做**滑动平均**（`SMOOTH_WIN=5`）去抖，再用中心差分求速度（单位 像素/秒）。
  - 直接用相邻两帧差分会把检测噪声放大 30 倍，箭头会乱抖。
- 速度映射成箭头长度时做了**限幅**：用全片速度的 **95% 分位**当"箭头最长"的标准，
  再线性映射到 `[25, 160]` 像素。
  - 直接 `L = k × v` 不加限幅是常见错误：本视频速度能到 800+ px/s，乘个系数箭头会戳出画面。

## 参数表

| 参数 | 默认值 | 含义 |
|---|---|---|
| `GREEN_LOW / HIGH` | (35,60,60) / (85,255,255) | 绿色在 HSV 空间的阈值 |
| `MIN_AREA` | 500 | 小于它的色块当噪点忽略 |
| `FILL_MIN` | 0.73 | 实心圆占比下限，区分球和圆柱 |
| `SMOOTH_WIN` | 5 | 平滑窗口（帧） |
| `ARROW_MIN / MAX` | 25 / 160 | 箭头长度范围（像素） |
| `SPEED_PERCENT` | 95 | 速度分位，决定"箭头最长"对应的速度 |

## 遇到的问题 / 说明

1. **两个绿色物体**：本题最大坑，用"实心圆占比"解决（见上）。
2. **箭头戳出画面**：速度 × 系数没限幅的后果，用分位归一化 + 双向 clamp 解决。
3. **低速短箭头被球挡住**：箭头改成从球边缘起画。
4. **视频编码**：`mp4v` 在部分播放器/浏览器打不开，可转 H.264：
   `ffmpeg -i output.mp4 -c:v libx264 -pix_fmt yuv420p output_h264.mp4`
