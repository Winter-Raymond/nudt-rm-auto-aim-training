## 三、实现思路

整个流程分四步，每一步对应代码里的一个函数。

### 第 1 步：把图像从 BGR 转到 HSV

```python
hsv = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)
```

**为什么不直接用 RGB？** 因为 RGB 三个通道混在一起，"绿色"的数值会随光照剧烈变化——亮一点的绿和暗一点的绿，RGB 值差得很远，很难用一个固定范围框住。

HSV 把三件事拆开了：

- **H（色相）**：颜色本身是什么，绿色大致在 35~90 这个区间
- **S（饱和度）**：颜色浓不浓，越低越接近白色/灰色
- **V（亮度）**：亮不亮，越低越接近黑色

拆开之后，只要按 H 通道筛选就能认出"绿色"，跟明暗无关，鲁棒性高很多。

### 第 2 步：做掩膜，把绿色区域抠出来

```python
mask = cv2.inRange(hsv, np.array((35, 60, 60)), np.array((90, 255, 255)))
```

`inRange` 逐个像素比对：落在区间内的设为 255（白），否则设为 0（黑）。结果是一张黑白图，白色的地方就是绿色区域。

然后做形态学去噪：

```python
kernel = np.ones((5, 5), np.uint8)
mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN, kernel)    # 开运算：去掉小白点噪点
mask = cv2.morphologyEx(mask, cv2.MORPH_CLOSE, kernel)   # 闭运算：填补小球内部的小黑洞
```

### 第 3 步：找轮廓，并挑出真正的球

这是本次作业**最关键的一步**，也是最容易被忽略的坑。

直觉做法是"取面积最大的绿色块"，但实测发现这样做是错的。诊断数据显示：

**视频里每一帧其实有两块绿色区域，它们同步运动（位移相关系数 0.992）：**

| 指标 | 第 1 大块 | 第 2 大块 |
| --- | --- | --- |
| 面积中位数 | 24123 | 11582 |
| 外接圆半径中位数 | 113 px | 65 px |
| 填充率（面积 / 外接圆面积） | 0.61 | **0.87** |
| 圆度 4πA/P² | 0.66 | **0.76** |
| 外接矩形宽高比 | 0.73（明显被拉长） | **1.00（正圆）** |

填充率越接近 1.0 说明越接近正圆。第 2 块填充率 0.87、宽高比 1.00，是标准的圆；第 1 块填充率只有 0.61、宽高比 0.73，是被拉长的不规则形状——那是小球快速运动留下的**运动拖影**。

用霍夫圆检测做交叉验证，结果一致：在第 1 帧检测到的圆是 `(654, 382, r=59)`，其圆心和面积（π·59² = 10936）与第 2 块（质心 `(652, 382)`，面积 10795）完全吻合；而第 1 块则被拆成了两个圆，说明它不是单一圆形。

所以代码里按**填充率筛选**，而不是按面积：

```python
fill = a / (np.pi * r * r)              # 填充率，1.0 = 正圆
round_ones = [c for c in candidates if c[0] >= MIN_FILL_RATIO]   # 只要够圆的
best = max(round_ones, key=lambda c: c[1])                        # 圆的里面挑最大的
```

另外加了**跳变保护**：如果某帧检测到的位置和上一帧相差超过 150 像素，判定为认错目标，该帧不参与速度计算，避免箭头乱飞。

### 第 4 步：算速度、画箭头

速度就是"位移 ÷ 时间"：

```python
vx = (x_now - x_old) / dt
vy = (y_now - y_old) / dt
```

直接取相邻两帧算会抖得厉害，所以取最近 5 帧做平均（`SMOOTH_WINDOW = 5`）。

画箭头用 `cv2.arrowedLine`，起点是球心，终点是球心加上速度向量：

```python
end_x = int(cx + vx * ARROW_SCALE)
end_y = int(cy + vy * ARROW_SCALE)
cv2.arrowedLine(img, (cx, cy), (end_x, end_y), (0, 255, 0), 2, tipLength=0.35)
```

这样**方向天然就是运动方向，长度天然正比于速度**，正好满足题目要求。

## 四、参数选择依据

参数不是拍脑袋定的，都是实测算出来的：

| 参数 | 取值 | 依据 |
| --- | --- | --- |
| `GREEN_LOWER` / `GREEN_UPPER` | (35,60,60) ~ (90,255,255) | 实测掩膜内像素 H 通道 5% 分位 65、中位 76、95% 分位 81，全落在区间内 |
| `MIN_CONTOUR_AREA` | 500 | 过滤掉小噪点（实测噪点面积多在 60~160） |
| `MIN_FILL_RATIO` | 0.70 | 真球 0.87、拖影 0.61，取中间值把两者分开 |
| `SMOOTH_WINDOW` | 5 | 太小箭头会抖，太大跟不上变速；5 帧（1/6 秒）实测方向中位误差 8.1° |
| `ARROW_SCALE` | 0.14 | 全片速度 95 分位约 712 px/s，712 × 0.14 ≈ 100 px，箭头长度适中 |
| `ARROW_MAX_LEN` | 150 | 实测最大速度 838 × 0.14 = 117 px，不会触发截断 |
| `MAX_JUMP` | 150 | 实测正常帧位移中位数 12 px，超过 150 判定为异常 |

## 九、遇到的问题与解决

| 问题 | 解决方式 |
| --- | --- |
| 直接用 RGB 找绿色，光照一变就失效 | 改用 HSV 色彩空间，只按 H 通道筛选 |
| 取"面积最大的绿色块"会跟到运动拖影上 | 加填充率筛选，只认填充率 ≥ 0.70 的圆形区域 |
| 相邻帧直接算速度，箭头抖动严重 | 取最近 5 帧位移做平均 |
| 个别帧位置跳变 200+ 像素，箭头乱飞 | 加跳变保护，超阈值帧不参与速度计算 |
| 想用 H.264 压缩输出视频 | 本机缺 OpenH264 库，改用 mp4v 编码 |

## 十、可调参数

想改效果，直接改 `green_ball_tracker.py` 顶部的参数区即可，不用动下面的逻辑：

- 箭头太长/太短 → 改 `ARROW_SCALE`
- 箭头太抖/太迟钝 → 改 `SMOOTH_WINDOW`
- 误识别了背景里的绿色 → 把 `GREEN_LOWER` 的 S、V 调高
- 不想显示轨迹尾巴 → `DRAW_TRAIL = False`
